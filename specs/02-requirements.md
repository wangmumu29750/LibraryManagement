## 1. 项目目标

在既有对话式图书管理系统基座（Python + FastAPI + SQLite，端口 8001）之上，以 Spec-Driven 方式完成：

1. 建立覆盖读者、图书管理员、系统管理员三类角色的需求基线；
2. 在基座已有能力（登录、检索、借书、还书、预约、查询借阅记录）之上，**新增"续借"与"图书评论与评分"两项功能**；
3. 所有业务规则集中在 Service / Policy 层，界面与 Controller 不含规则；
4. 每条功能需求具备可验证的验收标准，并由自动化测试或 curl 实测覆盖。

## 3. 功能需求

### FR-000 用户登录认证（基座已有）

系统应提供登录接口，校验用户名与密码，成功后返回用户标识与角色信息。

- **AC-000-1**：`POST /api/login`，`{"username":"zhangsan","password":"123456"}` → 返回 `success=true`，`data` 含 `user_id=1`、`role="reader"`、`max_borrow=5`。
- **AC-000-2**：密码错误 → 返回 `success=false`，`message="密码错误"`。
- **AC-000-3**：用户不存在 → 返回 `success=false`，`message="用户不存在"`。
- ⚠️ 偏差 D-01：本接口返回 `{success, message, data}`，未使用统一信封 `{code, message, data}`，第一阶段保持不变。

---

### FR-001 注册读者账号

读者应能注册账号，填写用户名、密码、姓名、读者类型、联系方式。

- **AC-001-1**：用户名未被占用 → 注册成功，系统生成唯一 `user_id`。
- **AC-001-2**：用户名已存在 → 拒绝并提示"用户名已存在"（违反唯一约束 BR-013）。
- **AC-001-3**：必填项缺失 → 拒绝并说明缺失字段。
- 编码范围：**仅建模，本期不实现代码**。

### FR-002 办理借阅证

系统管理员应为已注册读者办理借阅证，证号由系统生成。

- **AC-002-1**：为有效读者办证 → 生成证号 `CARD + 年份 + 6 位序号`（如 `CARD2026000001`）。
- **AC-002-2**：同一读者重复办证 → 拒绝（一人一证，BR-001）。
- **AC-002-3**：读者不存在 → 拒绝并提示。
- 编码范围：**仅建模，本期不实现代码**。

### FR-003 删除借阅证

系统管理员应能删除借阅证。

- **AC-003-1**：借阅证存在且**无在借记录** → 删除成功。
- **AC-003-2**：存在 `status = borrowing` 的记录 → 拒绝删除并提示"该读者尚有未归还图书"。
- 编码范围：**仅建模**。

### FR-004 / FR-005 添加 / 删除图书管理员

系统管理员应能维护图书管理员账号。

- **AC-004-1**：新增管理员，用户名唯一；重复则拒绝。
- **AC-005-1**：删除管理员时若其存在未完成的流通操作记录 → 拒绝并提示。
- 编码范围：**仅建模**。

### FR-006 / FR-007 添加 / 删除图书标题信息

系统管理员应能维护图书标题（书名、作者、ISBN、出版社、出版年、分类、馆藏位置、简介）。

- **AC-006-1**：ISBN 全局唯一，重复则拒绝（BR-013）。
- **AC-006-2**：必填项（书名、作者、ISBN）缺失 → 拒绝。
- **AC-007-1**：删除采用**逻辑删除**（`is_active = false`），已有借阅历史的标题不得物理删除。
- 编码范围：**仅建模**。

### FR-008 / FR-009 添加 / 删除馆藏副本

系统管理员应能维护馆藏副本（条码、所属标题、状态）。

- **AC-008-1**：新增副本 → 所属标题 `total_copies` 与 `available_copies` 同步 +1。
- **AC-008-2**：条码唯一，重复则拒绝（BR-013）。
- **AC-009-1**：处于 `borrowing` 状态的副本不得删除。
- 编码范围：**仅建模**。

### FR-010 查询图书（基座已有）

系统应支持按书名/ISBN/作者/分类/馆藏位置检索图书，支持分页。

- **AC-010-1**：`GET /api/books/search?keyword=三体` → `code=200`，`data.total >= 1`，命中《三体》。
- **AC-010-2**：无匹配 → `code=200`，`data.total = 0`，`data.books = []`（空结果不是错误）。
- **AC-010-3**：`GET /api/books/{book_id}` 图书不存在 → 返回 `404`（偏差 D-02）。
- **AC-010-4**：仅返回 `is_active = true` 的图书。

### FR-011 借阅图书（基座已有）

由图书管理员代理，为读者办理借书。

- **AC-011-1**：全部校验通过 → `code=200`，返回 `record_id`、`book_title`、`due_date`（`YYYY-MM-DD`）、`remaining_quota`。
- **AC-011-2**：读者不存在 → `code=400`，`message="用户不存在"`。
- **AC-011-3**：操作人为 `admin` → `code=400`，`message="管理员不能借书"`。
- **AC-011-4**：在借数量已达上限 → `code=400`，`message="借阅已满（5/5），请先归还图书"`。
- **AC-011-5**：存在超期未还记录 → `code=400`，`message="有N本图书超期未还，请先归还"`。
- **AC-011-6**：图书不存在 → `code=400`，`message="图书不存在"`。
- **AC-011-7**：可借副本为 0 → `code=400`，`message="图书已全部借出"`。
- **AC-011-8**：借书成功后 `available_copies` 减 1，并生成 `status = borrowing` 的借阅记录。
- ⚠️ 偏差 D-06：种子数据当前全部超期，借书前需先归还超期图书，否则命中 AC-011-5。

### FR-012 归还图书（基座已有）

由图书管理员代理办理还书，并计算超期罚款。

- **AC-012-1**：记录在借 → `code=200`，返回 `book_title`、`borrow_date`、`return_date`、`days_overdue`、`fine`。
- **AC-012-2**：记录不存在或已归还 → `code=400`，`message="借阅记录不存在或已归还"`。
- **AC-012-3**：归还后 `available_copies` 加 1，记录 `status = returned`，写入 `return_date`。
- **AC-012-4**：超期归还 → `fine = 超期天数 × 0.5 元`，`is_overdue = true`。
- **AC-012-5**：未超期归还 → `days_overdue = 0`，`fine = 0`。

### FR-013 查询借阅信息（基座已有）

读者可查询本人借阅记录，图书管理员/系统管理员可查询指定读者记录。

- **AC-013-1**：`GET /api/borrow/records/{user_id}` → `code=200`，`data.records` 含 `record_id`、`book_title`、`borrow_date`、`due_date`、`return_date`、`status`、`is_overdue`。
- **AC-013-2**：支持 `status` 过滤（`borrowing` / `returned` / `reserved`）。
- **AC-013-3**：`GET /api/borrow/check-quota/{user_id}` → 返回 `current_borrowed`、`max_borrow`、`remaining`、`has_overdue`、`overdue_count`。

### FR-014 预约图书（基座已有）

读者可预约已全部借出的图书，按时间排队。

- **AC-014-1**：图书可借副本为 0 且未重复预约 → `code=200`，`message="预约成功，图书到馆后将通知您"`，生成 `status = reserved` 记录。
- **AC-014-2**：图书在馆（`available_copies > 0`）→ `code=400`，`message="图书在馆，请直接借阅"`。
- **AC-014-3**：同一读者重复预约同一本书 → `code=400`，`message="您已经预约过这本书了"`。
- **AC-014-4**：预约有效期 7 天，超期自动失效并按创建时间顺延下一位（BR-007、BR-008）。
- ⚠️ 偏差 D-04：基座复用 `borrow_records` 表存预约（无独立 `reservations` 表），specs 中建模独立表，实现沿用基座。

### FR-015 计算超期罚款（基座部分实现）

系统应在归还时按规则计算超期罚款。

- **AC-015-1**：按自然日计算超期天数，无宽限期。
- **AC-015-2**：中文图书 0.5 元/天；外文图书 1.0 元/天；中文杂志 0.2 元/天；外文杂志 0.5 元/天；论文 2.0 元/天（BR-006）。
- **AC-015-3**：罚款上限为图书定价的 2 倍，无定价时上限 100 元。
- **AC-015-4**：存在未缴罚款时禁止继续借书（本期以"存在超期未还记录"近似，BR-004）。
- ⚠️ 偏差 D-03：基座统一按 0.5 元/天计算，差异化规则写入 `fine_rules` 表设计，本期代码沿用单一规则。

### FR-016 维护借阅规则和罚款规则

系统管理员应能配置不同读者类型的借阅数量/期限，以及不同借出物类型的罚款规则。

- **AC-016-1**：可按读者类型配置 `max_borrow` 与借阅天数（BR-002）。
- **AC-016-2**：可按借出物类型配置日罚款额与上限（BR-006）。
- **AC-016-3**：修改后的规则对后续借阅/归还操作生效，不影响已有记录。
- 编码范围：**仅建模**（本期以初始化常量数据表达规则）。

### FR-017 续借图书 ✨（本次新增功能一）

读者可对**在借**的图书申请续借，系统延长应还日期并返回新的应还日期。

- **AC-017-1**：记录状态为 `borrowing` 且符合续借条件 → `code=200`，返回 `due_date`（新的应还日期，`YYYY-MM-DD`）。
- **AC-017-2**：记录状态为 `returned`（已归还）→ `code=400`，`message="该借阅记录已归还，无法续借"`。
- **AC-017-3**：记录不存在 → `code=400`，`message="借阅记录不存在"`。
- **AC-017-4**：续借天数固定延长 **30 天**，每本书**最多续借 1 次**（BR-009）。
- **AC-017-5**：已超过续借次数上限 → `code=400`，`message="该书已达最大续借次数"`。
- **AC-017-6**：该图书已被他人预约 → `code=400`，`message="该书已被预约，无法续借"`。
- **AC-017-7**：已超期（`now > due_date` 且仍为 `borrowing`）→ `code=400`，`message="该图书已超期，无法续借，请先归还"`。**（方案 A：超期不可续借）**
- **AC-017-8**：Agent 侧：用户说"把我借的《三体》续借一下" → `orchestrator-agent` **委派 `circulation-agent`** 执行，先查在借记录取 `record_id`，再调续借接口，回复中包含新的应还日期。
- 编码范围：**本期必须实现**。
- ⚠️ **演示路径（方案 A，因 D-06 种子数据全部超期）**：先归还超期图书（FR-012）→ 重新借阅一本（`due_date = 今天 + 30 天`）→ 再对该记录续借。禁止直接对种子记录续借，否则必命中 AC-017-7。

### FR-018 写图书评论与评分 ✨（本次新增功能二）

读者可对图书打 1–5 分并撰写评论。

- **AC-018-1**：评分在 1–5 之间 → 保存成功，`code=200`，返回 `review_id`。
- **AC-018-2**：评分 < 1 或 > 5 → `code=400`，`message="评分必须在 1-5 之间"`（由**后端**拒绝，非前端校验）。
- **AC-018-3**：同一读者对同一本书重复提交 → **覆盖更新**已有评论（BR-010）。
- **AC-018-4**：评论内容可为空（只评分不写评论）。
- **AC-018-5**：Agent 侧：用户说"给《三体》打 5 分，写句评论：太好看了" → 编排层以 **`use_skill`** 方式调用评论 skill（**不委派 circulation-agent**）。
- 编码范围：**本期必须实现**。

### FR-019 查看图书评论与平均评分 ✨（本次新增功能二）

用户可查看某本图书的全部评论与平均评分。

- **AC-019-1**：`code=200`，`data` 含 `average_rating`（**保留 1 位小数**，如 `4.5`）、`total`（评论条数）、`reviews`（评论列表，含用户名、评分、内容、时间）。
- **AC-019-2**：该书无任何评论 → `code=200`，`average_rating = 0.0`，`total = 0`，`reviews = []`。
- **AC-019-3**：平均分 = 全部评分的算术平均，由**后端计算**（BR-011）。
- **AC-019-4**：字段名 `average_rating` / `total` / `reviews` 在后端、`14-api-spec.md`、评论 skill 三处**必须一致**（宪法第 9 条）。
- 编码范围：**本期必须实现**。

## 5. 业务规则

| 编号 | 规则 | 归属层 |
|---|---|---|
| BR-001 | 一证一人、一人一证；借阅证号 `CARD + 年份 + 6 位序号` 全局唯一 | Policy / Service |
| BR-002 | 借阅数量与期限：本科 5 本/30 天；研究生 10 本/60 天；博士生 15 本/90 天；专科生 5 本/30 天；教师 20 本/90 天 | BorrowPolicy |
| BR-003 | 借书校验：① 读者存在且非管理员；② 未超配额；③ 无超期未还；④ 副本可借（`available_copies > 0`）；⑤ 图书 `is_active = true` | Service |
| BR-004 | 超期判定：`now > due_date` 且状态仍为 `borrowing`；存在超期记录时禁止新借 | Service |
| BR-005 | 归还：状态置 `returned`、写入 `return_date`、副本可借数 +1、计算罚款 | Service |
| BR-006 | 罚款：按借出物类型日费率 × 超期自然日，上限为定价 2 倍（无定价则 100 元）；无宽限期 | FineRule |
| BR-007 | 预约：仅在全部副本借出时可预约；同一读者对同一标题不可重复预约；按创建时间 FIFO 排队 | Service |
| BR-008 | 预约有效期 7 天，逾期自动失效并顺延下一位；本期不实现严格锁库 | Service |
| BR-009 | **续借（方案 A，已定稿）**：仅 `borrowing` 可续；每次 +30 天；每本最多 1 次；**已超期不可续**；已被预约不可续。演示须遵循 FR-017 的"演示路径"（先还超期书 → 再借 → 再续） | Service / Policy |
| BR-010 | 评分：整数 1–5，越界拒绝；同一读者对同一图书仅保留一条评论（联合唯一约束） | Service |
| BR-011 | 平均分：后端按 `round(avg, 1)` 计算，无评论时为 `0.0` | Service |
| BR-012 | 权限矩阵见第 2 节；越权返回业务错误，不得静默放行 | Service |
| BR-013 | 唯一约束：`readers.username`、`book_titles.isbn`、`borrow_cards.card_no`、`library_items.barcode`、`reviews(user_id, book_id)` | 数据库 |
