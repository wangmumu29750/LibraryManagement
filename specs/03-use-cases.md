## 4. 详细用例文本

### UC-101 办理借书 ⭐ 重点

| 项 | 内容 |
|---|---|
| **用例编号** | UC-101 |
| **用例名称** | 办理借书 |
| **主要参与者** | 图书管理员（Librarian） |
| **次要参与者** | 读者（Reader，业务受益方） |
| **关联需求** | FR-011、BR-002、BR-003、BR-004、BR-013 |
| **前置条件** | ① 图书管理员已登录；② 读者持有有效借阅证；③ 系统已配置该读者类型的借阅规则 |
| **后置条件（成功）** | 生成一条 `status = borrowing` 的借阅记录；该图书 `available_copies` 减 1；读者在借数量加 1 |

**基本事件流**

1. 读者提出借书请求，图书管理员启动"办理借书"。
2. 管理员输入读者标识（`user_id`）或借阅证号。
3. 系统**验证借阅证**（UC-120）：证号存在且有效。
4. 系统显示读者信息（姓名、读者类型、当前在借数量、配额）。
5. 系统**检查借阅规则**（UC-121）：
   1. 校验读者存在且角色不是 `admin`；
   2. 校验在借数量未超过该读者类型的 `max_borrow`；
   3. 校验不存在超期未还记录（`now > due_date` 且状态为 `borrowing`）。
6. 管理员输入待借图书标识（`book_id`）。
7. 系统校验图书存在、`is_active = true` 且 `available_copies > 0`。
8. 系统创建借阅记录：`borrow_date = now`、`due_date = now + 借阅期限`、`status = borrowing`。
9. 系统将图书 `available_copies` 减 1。
10. 系统返回 `record_id`、`book_title`、`due_date`、`remaining_quota`，用例成功结束。

**备选事件流**

- 4a. 读者信息不存在 → 转异常 4a。
- 7a. 该图书所有副本已借出，但读者愿意预约 → 转入 UC-004 预约图书。
- 8a. 读者类型对应的借阅期限按 BR-002 取值（本期统一 30 天）。

**异常事件流**

- 2a. 读者不存在 → `code=400`，`message="用户不存在"`，用例终止。
- 5a. 操作人为管理员 → `code=400`，`message="管理员不能借书"`。
- 5b. 已达借阅上限 → `code=400`，`message="借阅已满（N/M），请先归还图书"`。
- 5c. 存在超期未还记录 → `code=400`，`message="有N本图书超期未还，请先归还"`。
- 7b. 图书不存在或已下架 → `code=400`，`message="图书不存在"`。
- 7c. 副本全部借出且不愿预约 → `code=400`，`message="图书已全部借出"`。
- 9a. 数据库写入失败 → 事务回滚，`code=500`，`message="借阅失败：…"`。

> ⚠️ 偏差 D-06：当前种子借阅记录全部超期，首次演示会命中 5c。演示前须先执行 UC-102 归还超期图书。

### UC-102 办理还书 ⭐ 重点

| 项 | 内容 |
|---|---|
| **用例编号** | UC-102 |
| **用例名称** | 办理还书 |
| **主要参与者** | 图书管理员（Librarian） |
| **次要参与者** | 读者（Reader） |
| **关联需求** | FR-012、FR-015、BR-005、BR-006 |
| **前置条件** | 图书管理员已登录；存在 `status = borrowing` 的借阅记录 |
| **后置条件（成功）** | 记录状态置为 `returned`、写入 `return_date`；图书 `available_copies` 加 1；产生罚款金额（可为 0） |

**基本事件流**

1. 管理员启动"办理还书"，输入借阅记录标识（`record_id`）或扫描图书。
2. 系统校验记录存在且状态为 `borrowing`。
3. 系统校验该图书为本馆藏书（记录关联 `book_id` 有效）。
4. 系统置 `status = returned`，写入 `return_date = now`。
5. 系统**计算超期罚款**（UC-110）。
6. 系统将图书 `available_copies` 加 1。
7. 系统返回 `book_title`、`borrow_date`、`return_date`、`days_overdue`、`fine`，用例成功结束。

**备选事件流**

- 1a. 管理员先查询该读者的在借记录（UC-103），再选择目标记录。
- 5a. 未超期 → `days_overdue = 0`、`fine = 0`，直接返回。

**异常事件流**

- 2a. 记录不存在或已归还 → `code=400`，`message="借阅记录不存在或已归还"`。
- 3a. 图书非本馆藏书 → 拒绝并提示"非本馆藏书"。
- 6a. 数据库写入失败 → 事务回滚，`code=500`，`message="归还失败：…"`。

### UC-110 计算超期罚款 ⭐ 重点（被 UC-102 include）

| 项 | 内容 |
|---|---|
| **用例编号** | UC-110 |
| **用例名称** | 计算超期罚款 |
| **主要参与者** | 系统（由 UC-102 触发） |
| **次要参与者** | — |
| **关联需求** | FR-015、BR-006 |
| **前置条件** | 已进入还书流程，且已知 `due_date` 与当前日期 |
| **后置条件（成功）** | 得出 `days_overdue` 与 `fine`，并回写记录 `is_overdue` |

**基本事件流**

1. 系统比较当前日期与 `due_date`。
2. 若 `now <= due_date` → `days_overdue = 0`，`fine = 0`，直接返回。
3. 若 `now > due_date` → `days_overdue = (now - due_date).days`。
4. 系统按借出物类型取日罚款费率（BR-006）：中文图书 0.5 元/天；外文图书 1.0 元/天；中文杂志 0.2 元/天；外文杂志 0.5 元/天；论文 2.0 元/天。
5. 系统计算 `fine = days_overdue × 费率`。
6. 系统按罚款上限（定价 2 倍，无定价则 100 元）截断。
7. 系统回写 `is_overdue = true`，返回 `days_overdue` 与 `fine`。

**异常事件流**

- 4a. 该借出物类型未配置费率 → 取默认费率 0.5 元/天并记录告警。

> ⚠️ 偏差 D-03：基座统一按 0.5 元/天计算，本期沿用；差异化费率仅在 `fine_rules` 表设计中体现。

### UC-104 办理续借 ⭐ 重点（本次新增功能）

| 项 | 内容 |
|---|---|
| **用例编号** | UC-104 |
| **用例名称** | 办理续借 |
| **主要参与者** | 图书管理员（Librarian）；对话入口由读者发起 |
| **次要参与者** | 读者（Reader） |
| **关联需求** | FR-017、BR-009、AC-017-1 ~ AC-017-8 |
| **前置条件** | ① 读者已登录；② 存在该读者名下 `status = borrowing` 的借阅记录；③ 该记录未超期、未达续借次数上限、对应图书未被他人预约 |
| **后置条件（成功）** | 该借阅记录 `due_date` 延长 30 天，`renew_count` 加 1；系统返回新的应还日期 |

**基本事件流（对话入口）**

1. 读者用自然语言提出请求，例如"把我借的《三体》续借一下"。
2. `orchestrator-agent` 识别意图为"续借"，**委派给 `circulation-agent`**。
3. `circulation-agent` 先调用查询借阅记录接口，按书名与 `status = borrowing` 定位到目标记录，取得 `record_id`。
4. `circulation-agent` 调用续借接口，传入 `record_id`（及可选续借天数）。
5. 系统**验证借阅证**（UC-120）并**检查续借规则**（UC-122）：
   1. 记录存在且状态为 `borrowing`；
   2. 未超过最大续借次数（1 次）；
   3. 当前日期未超过 `due_date`（未超期）；
   4. 该图书不存在他人的 `reserved` 预约记录。
6. 系统将 `due_date` 延长 30 天，`renew_count` 加 1，持久化。
7. 系统返回 `code=200` 与新的 `due_date`。
8. `circulation-agent` 将结果回传，`orchestrator-agent` 聚合为自然语言回复："续借成功！新的应还日期为 XXXX-XX-XX。"

**备选事件流**

- 3a. 同名图书有多条在借记录 → 列出记录让用户确认后再续借。
- 4a. 接口接受可选的续借天数参数，未传时按默认 30 天处理。

**异常事件流**

- 3b. 未找到在借记录 → `code=400`，`message="未找到该书的在借记录"`。
- 5a. 记录已归还（`status = returned`）→ `code=400`，`message="该借阅记录已归还，无法续借"`（AC-017-2）。
- 5b. 已达最大续借次数 → `code=400`，`message="该书已达最大续借次数"`（AC-017-5）。
- 5c. 已超期 → `code=400`，`message="该图书已超期，无法续借，请先归还"`（AC-017-7，方案 A）。
- 5d. 已被他人预约 → `code=400`，`message="该书已被预约，无法续借"`（AC-017-6）。
- 6a. 数据库写入失败 → 回滚，`code=500`，`message="续借失败：…"`。

> ⚠️ 演示路径（方案 A / D-06）：**先归还超期图书（UC-102）→ 重新借阅（UC-101，due = 今天+30）→ 再执行本用例**。

### UC-004 预约图书 ⭐ 重点

| 项 | 内容 |
|---|---|
| **用例编号** | UC-004 |
| **用例名称** | 预约图书 |
| **主要参与者** | 读者（Reader） |
| **次要参与者** | — |
| **关联需求** | FR-014、BR-007、BR-008 |
| **前置条件** | 读者已登录；目标图书当前 `available_copies = 0`（全部借出） |
| **后置条件（成功）** | 生成一条 `status = reserved` 的预约记录，进入该书预约队列 |

**基本事件流**

1. 读者查询图书（UC-002），选择一本当前不可借的图书。
2. 读者发起预约。
3. 系统校验图书存在且 `is_active = true`。
4. 系统校验 `available_copies = 0`（在馆则不允许预约）。
5. 系统校验该读者对该书无未失效的重复预约。
6. 系统创建预约记录：`status = reserved`、`borrow_date = now`、`due_date = now + 7 天`（预约有效期）。
7. 系统返回 `code=200`、`message="预约成功，图书到馆后将通知您"`、`record_id`。

**备选事件流**

- 4a. 图书在馆 → 引导读者直接借阅（转 UC-101）。

**异常事件流**

- 3a. 图书不存在 → `code=400`，`message="图书不存在"`。
- 4b. 图书在馆 → `code=400`，`message="图书在馆，请直接借阅"`（AC-014-2）。
- 5a. 重复预约 → `code=400`，`message="您已经预约过这本书了"`（AC-014-3）。
- 6a. 预约有效期到期未借 → 自动失效，队列按创建时间顺延下一位（BR-008）。

> ⚠️ 偏差 D-04：基座复用 `borrow_records` 表存预约（`status = reserved`），无独立 `reservations` 表。

### UC-201 办理借阅证 ⭐ 重点

| 项 | 内容 |
|---|---|
| **用例编号** | UC-201 |
| **用例名称** | 办理借阅证 |
| **主要参与者** | 系统管理员（SystemAdmin） |
| **次要参与者** | 读者（Reader） |
| **关联需求** | FR-002、BR-001、AC-002-1 ~ AC-002-3 |
| **前置条件** | 系统管理员已登录；读者已完成账号注册（UC-001） |
| **后置条件（成功）** | 为该读者生成唯一借阅证记录，证号写入 `borrow_cards.card_no` |

**基本事件流**

1. 管理员启动"办理借阅证"，输入读者标识。
2. 系统校验读者存在且状态正常。
3. 系统校验该读者尚未持有有效借阅证（一人一证）。
4. 系统生成证号：`CARD + 年份 + 6 位序号`（如 `CARD2026000001`）。
5. 系统按读者类型设置有效期（学生默认 4 年，教师默认 10 年）。
6. 系统保存借阅证并显示证号与有效期，用例成功结束。

**异常事件流**

- 2a. 读者不存在 → 拒绝并提示"读者不存在"。
- 3a. 该读者已持有借阅证 → 拒绝并提示"该读者已办理借阅证"（AC-002-2）。
- 4a. 证号生成冲突 → 重新生成（唯一约束 BR-013）。
