## A. 参与者与角色（Actor）

**Q1 ⭐ 系统共有哪些参与者？**
建议：读者（Reader）、学生读者（StudentReader）、教师读者（TeacherReader）、图书管理员（Librarian）、系统管理员（SystemAdmin）。是否需要再区分"游客（未登录）"？

**Q2 ⭐ 学生读者是否需要进一步细分为本科生 / 研究生 / 博士生 / 专科生？**
Project Brief 第 5 节列出了 4 类，但它们是否作为独立的参与者子类，还是仅作为读者的一个"读者类型"属性？

**Q3 图书管理员与系统管理员是否为同一批人？**
即：一个账号能否同时拥有两种角色？

**Q4 读者能否自助借书、还书？**
还是必须由图书管理员代理完成？Project Brief 与实验要求中写的是"图书管理员作为代理"，请确认是否允许读者自助。

**Q5 是否需要考虑"游客"浏览/检索图书？**
未登录用户能否查询馆藏？

## B. 用例范围（Use Case）

**Q6 ⭐ 本次实验必须实现的用例清单是什么？**
建议范围（与实验指导书一致）：注册账号、办理/删除借阅证、添加/删除图书管理员、添加/删除图书标题、添加/删除馆藏副本、查询图书、借阅图书、归还图书、**续借图书**、查询借阅信息、预约图书、计算超期罚款、维护借阅规则与罚款规则、**写图书评论与评分**、**查看图书评论与平均分**。是否全部纳入？有无裁剪？

**Q7 是否需要"注销/停用读者账号"用例？**

**Q8 是否需要"取消预约"用例？**
若需要，取消后排队队列如何处理（后面的人是否自动递补）？

**Q9 是否需要"缴纳罚款"用例？**
还是只计算并生成罚款记录，不实现缴款流程？

**Q10 是否需要"挂失/补办借阅证"用例？**

## C. 业务规则 —— 借阅证

**Q11 ⭐ 借阅证号如何生成？**
建议：`CARD + 年份 + 6 位序号`，如 `CARD2024000001`。是否采纳？

**Q12 ⭐ 借阅证的有效期是多久？过期后如何续期？**

**Q13 借阅证是否必须"先办证后借书"？**
无借阅证的读者能否借书？

**Q14 一张借阅证是否严格绑定一个读者？**
是否允许一证多人、一人多证？

---

## D. 借阅规则（BorrowPolicy）

**Q15 ⭐ 每种读者类型的最大借阅数量与借阅期限分别是多少？**
建议值：本科生 5 本 / 30 天；研究生 10 本 / 60 天；博士生 15 本 / 90 天；专科生 5 本 / 30 天；教师 20 本 / 90 天。请确认或给出你的数值。

**Q16 ⭐ 借书时必须做哪些校验？**
建议：① 借阅证存在且有效；② 未超过该读者类型的最大借阅数量；③ 不存在超期未还图书；④ 馆藏副本状态为"可借"。是否还有其他？

**Q17 ⭐ 续借规则是什么？**
- 每本书最多可续借几次？
- 每次续借延长多少天（是否等于原借阅期限）？
- 已超期的图书能否续借？
- 已被他人预约的图书能否续借？

**Q18 同一读者能否重复借同一本图书标题的不同副本？**

**Q19 借书时是否需要图书管理员身份验证（记录经手人）？**

---

## E. 罚款规则（FineRule）

**Q20 ⭐ 各借出物类型的超期罚款规则是什么？**
建议：中文图书 0.5 元/天；外文图书 1.0 元/天；中文杂志 0.2 元/天；外文杂志 0.5 元/天；论文 2.0 元/天。是否设置罚款上限（如不超过图书定价的 2 倍）？

**Q21 罚款是按自然日计算，还是有宽限期（如超期 3 天内不罚款）？**

**Q22 图书丢失/损坏如何赔偿？**
是否按定价倍数赔偿（如 2 倍）？

**Q23 罚款是否必须由读者缴纳后才能继续借书？**
即：存在未缴罚款时，是否禁止借阅？

---

## F. 预约规则（Reservation）

**Q24 ⭐ 是否允许多人对同一图书标题排队预约？**
建议：允许，按预约创建时间排队（FIFO）。

**Q25 预约是否有有效期？**
图书归还后为第一顺位读者保留多少天（如 7 天），逾期未借则自动失效并顺延给下一位？

**Q26 预约的粒度是"图书标题（BookTitle）"还是"馆藏副本（LibraryItem）"？**

**Q27 已预约的图书，他人能否抢先借走？**

---

## G. 权限（Permission）

**Q28 ⭐ 各角色的权限边界如何划分？**
建议：读者＝查书/预约/查自己借阅记录/写评论；图书管理员＝代理借书、还书、续借、查询任意读者借阅信息；系统管理员＝办证、维护图书、维护管理员、维护规则。是否认可？

**Q29 ⭐ 第一阶段是否需要真实的登录认证（密码加密、Token/Session）？**
若不做真实认证，是否允许接口通过 `user_id` / `librarian_id` / `admin_id` 显式表示操作人？

**Q30 越权访问应如何响应？**
如读者调用管理员接口，返回什么？

---

## H. 评论与评分（新增功能）

**Q31 ⭐ 评分的取值范围与粒度？**
建议：整数 1–5 分。是否允许小数（如 4.5）？

**Q32 同一读者能否对同一本书多次评论？**
是覆盖更新，还是允许多条？

**Q33 评论是否需要审核（先审后发）？**

**Q34 未借过该书的读者能否评论？**

**Q35 "平均评分"如何呈现？**
需返回平均分（保留几位小数）与评论总条数吗？

## I. 数据（Data）

**Q36 ⭐ 需要持久化哪些实体？**
建议：readers、borrow_cards、librarians、system_admins、book_titles、library_items、loans、reservations、borrow_policies、fine_rules、fine_records、reviews。是否齐全？

**Q37 图书"标题信息"与"馆藏副本"如何区分？**
一本《三体》有 3 本副本，是 1 条 BookTitle + 3 条 LibraryItem 吗？

**Q38 借阅记录（Loan）需要保存历史吗？**
归还后是删除记录、标记状态为"已还"，还是归档到历史表？

**Q39 唯一约束有哪些？**
建议：`borrow_cards.card_no` 唯一、`library_items.barcode` 唯一、`readers.username` 唯一、`book_titles.isbn` 唯一。是否认可？

## J. 架构与技术（Architecture）

**Q40 ⭐ 技术栈是否确定为 Python 3.10+ / FastAPI / SQLAlchemy / SQLite / pytest？**
（课程主线为 Java 17 + Spring Boot 3，请确认选择。）

**Q41 ⭐ 是否严格采用四层分层架构 + MVC？**
建议：Presentation（Controller）/ Application Service / Domain / Infrastructure（Repository），Controller 不得直接依赖 Repository，业务规则集中在 Domain 的 Policy 或 Application Service。

**Q42 是否引入 Agent 对话层？**
基座已提供 `orchestrator-agent`（意图识别与路由）与 `circulation-agent`（流通执行）。续借走 circulation-agent、评论评分走 use_skill，是否确认？

**Q43 统一响应信封是否为 `{code, message, data}`？**
约定 `code==200` 成功、`code==400` 业务错误（message 原样透传用户）、`code==500` 系统错误。是否确认？

## K. 测试（Test）

**Q44 ⭐ 哪些用例必须有自动化测试？**
建议至少覆盖：办理借书成功、超量借书失败、有超期书借书失败、办理还书、超期罚款计算、续借成功、续借已还图书失败、预约排队、评分越界被拒、权限不足被拒。

**Q45 测试框架与方式？**
建议：pytest + httpx 对 FastAPI 接口做集成测试；是否需要单元测试覆盖领域服务？

**Q46 是否需要性能/并发测试（如多人同时预约同一本书）？**

## L. 教学复杂度（Scope Control）

**Q47 ⭐ 为了控制工作量，哪些内容明确不实现？**
建议沿用 Project Brief 第 8 节：真实支付扣款、条码扫描硬件、复杂全文检索、多校区调拨、微信/统一身份认证。是否还有补充（如消息通知、报表统计、图书推荐）？

**Q48 借阅规则与罚款规则需要做成"可在系统内配置"吗？**
还是硬编码为常量表初始化数据即可？

**Q49 是否需要 Web 前端界面？**
还是仅提供 REST API + Agent 对话入口？

**Q50 领域模型的继承关系要表达到什么程度？**
是否必须体现 `Reader → StudentReader/TeacherReader`、`LibraryItem → Book/Magazine/Thesis` 的继承，还是用类型字段（枚举）简化？
